# 复盘：特征取自首喊后 30s 的「决策截面」，结果只看其后 24h，输出关联而非原因

「复盘」页回答的是：过去 N 小时首喊的币里，首喊后 24h 峰倍 ≥ win 的那批（达标组）与其余相比，哪些**在首喊时就能看到**的特征出现得更多。三条硬约束：

1. **特征只用决策截面**。引擎在 live 首喊后 `CUT_SEC = 30` 秒把当时内存里的行情 / 官推资料 / 已抓推文数 / GMGN 喊单 / fomo 关注者信号 / gmgn 前排结构定格成 `token_snapshot`（每个来源带自己的观测时刻 `at`，`at` 晚于截面的字段视为缺失）。`tokens` 表里的粉丝数 / 持有人数是覆盖式最新值，拉升后会变，直接拿来解释「为什么涨」就是拿结果解释结果。回灌首喊没有截面 → 只有基准市值 / 喊单人先验 / 过程类特征可判定，其余计 missing，不是 0。唯二的例外是官推链接有无与账号注册日期——它们不随拉升改变，无截面时按事后资料补。
2. **结果只看 `[截面, 截面 + 24h]`**。`peakX24` = 窗口内采样最高 mc ÷ 截面 mc（无截面按首喊那条 `calls.mc`）；没满 24h 的币标「进行中」只列不比；窗口内实时采样 < 10 点标「采样不足」；两类坏点剔除——隐含供应量（mc ÷ price）与基准差 3 倍以上的点（DexScreener ↔ gmgn 供应量口径跳变会让 mc 在 price 不动时跳一两个数量级，真库里一个 3 点的币曾因此显示 33×），以及错币报价段（相对上一保留点一步跳 ≥20× 且 10 分钟内跳回来——回到原位或反向再一步跳 ≥20×；供应量一致所以第一道抓不到。真库 30d 扫描出 LUNA / HEMI / KEYCAT / NEKO 四个同名 meme 被按上市大币的价报了 1–8 个点、最长 200s，都在（重新）进面板后的第一批采样；HEMI 一段 1400× 的假报价能让不设止损的尾仓「赚」$69K。跳上去不回来的保留，那是真拉升）。另报「观测持续翻倍」：≥2× 的连续实时点串（相邻 ≤60s）跨度 ≥180s，采样来源未知（`samples.src` 为 NULL 的老行）→ null。
3. **只报关联**。每个特征给两组各自的 n / 达标 / 率 / Wilson95 与缺失数；任一组 n < 20 只报计数不排序；不做 logistic / AUC / 跨类型事件权重排名；页面与 markdown 都写「关联，不是因果」——样本只含被监听群喊过的币，「被喊」本身就是最强的共同特征。时间线把拉升起点（首次观测 ≥1.5×）前 60min 的事件按类型分栏列出，交给人判断。
4. **模拟交易不按基准价成交，卖出按仓位而不是按「一次清仓」，结果必须能按日拆开看**（独立页，与复盘分开：复盘是读一遍的诊断，模拟是反复调参）。入场在结果起点后 ≥20s 的第一个采样价：一是反应延迟，二是新币的首个 DexScreener 报价常滞后 gmgn 一两个数量级（真库 NINA：首喊 $3.2K，1s 后 gmgn $53K；按 $3.2K「买入」立刻 16× 止盈是假成交）。去掉这一层后，同一套「全部合格币 · 止盈 2× · 止损 0.5×」在 72h 上从 +$4,547 变成 −$649——之前的利润几乎全是滞后报价的幻觉。卖出支持多腿分批（到 x 倍卖原始仓位的 p%，「出本」= 1/x，可叠）与尾仓持有至今按现价估值：真库 7d 同一批 586 币「2× 全清」+$2,062，「2× 出本 + 尾仓至今」+$7,082，「2× 出本 + 4× 卖 25% + 尾仓至今」+$4,398——按日拆开，8 天里只有 09-12 一天是正的大数（+$9,973 / +$5,348），全靠 PERPSPAD 一个币的未实现，去掉每天最好一笔后 8 天只剩 1 天盈利。所以结果带已实现 / 未实现拆分、`exBest`（去掉最好一笔）和 `days[]`（按入场日、页面时区）。规则顺序止损 → 回撤 → 分批 → 止盈 → 到期；到期按截止点前最后采样卖，最后采样离截止 >120s 才算「覆盖不足」（此前入场晚 20s 导致所有 24h 持有都被标成覆盖不足）。

## Considered Options

- 用 t0 那一刻做特征：行情 0.4–0.8s、社交 2–10s、fomo 前排 ≤15s 才到，t0 时刻几乎全空；30s 截面把首 30s 的拉升信息泄漏进特征的代价可忽略（结果也从截面起算）。曾考虑 120s / 双截面，多出的只是更多泄漏。
- 用市场 24h 涨幅榜做研究对象：代码里没有 gmgn 榜单接口，且群 / 买入人数据只覆盖被喊过的币；即便接上，也只能回答「榜上的币有多少被我们群喊过、喊得早不早」。留作后续。
- 全库改成 `(chain, address)` 身份：CONTEXT 规定同址异链是两个币，但 `tokens` / `calls` / `samples` / 引擎索引都按 address 键，迁移横切全引擎。折中：新表 `token_snapshot` / `social_event` 按 `(chain, address)` 键，截面链 ≠ 当前 `tokens.chain` 的币在分析里隔离（`chain_conflict`），旧表不迁移、记为局限。
- 把推文 / GMGN 喊单也塞进快照 JSON：它们是事件不是状态，而且 `tokens.official/tweets` 每次刷新整体覆盖会丢历史，所以单独 append-only 的 `social_event`（`ref` 带 `tw:` / `gm:` 命名空间，同一推文社区 → 官方只升级 kind）。群喊单 / fomo 活动已有表，查询时合并，不复制第二份真相。
- LLM 自动写「涨的原因」：没有现成依赖，且会把关联包装成因果；先把结构化材料（dashboard + 页面上「复制 Markdown」）做好，要讨论就把 markdown 贴给人 / 模型。所有入口都在 UI 上，不给用户 CLI 命令。

## Consequences

- 新表与 `samples.src` 列从部署起累积；部署前的币只有群 / 基准市值 / 先验 / 过程类特征，推特 / 买入人类特征要等新截面攒到两组各 ≥20 才会出现 lift。
- 每个 live 新币多两次 gmgn 请求（前排 + GMGN 喊单首页，链确认时预拉，进各自缓存）；焦点时不再重复拉 60s 内的 GMGN 喊单。
- 24h 战况页的峰倍（`MAX(samples.mc)`）没有做供应量一致性剔除，同一个币两页可能显示不同峰倍；那边是否套用同一剔除另议。
